Everything that's landed since
[v1.1.0](https://github.com/Health-Flare/InnerFlare/releases/tag/v1.1.0): a
much more capable, customizable dashboard (gauge and trend cards, one
resizable grid), clearer charts, a tidier Settings, and the first build

## Full release notes

### A dashboard that fits how you track

- **Gauge cards** show either days since your last period or the estimated
  days until your next one, filled relative to your own average cycle
  length rather than a fixed scale. With thin history they show a range
  instead of false precision.
- **Trend cards** chart your previous cycle lengths as bars or a line, with
  a dashed line for your average. They never draw a trend from too little
  history.
- **Add a card** lets you add as many as you like, including more than one
  of the same kind (for example, two trend cards).
- **Quick stats, Calendar and Insights** now live in the same grid as every
  other card, as equal peers, instead of a separate row above them.
- **Resize any card** from Customize dashboard: press and hold a card's
  corner grip and drag to make it half or full width, or up to three rows
  tall. The grid reflows as you drag and remembers your layout.
- **Show, hide and reorder** work exactly as before.

### Charts you can read

Bar and line charts now have axis scales and legends, so you can tell what
is plotted and at what scale.

### A cycle-by-cycle table, for appointments

Tap a trend card and it opens a table of each complete cycle: its length,
and the difference from the cycle before. It is a record of what you
logged, made easy to hand to a clinician. It states plainly that it is not
a diagnosis.

### Auto-lock has its own page

Auto-lock settings moved out of the main Settings list onto a page of their
own. Behavior is unchanged: the default is still 15 minutes, and Settings
still shows the current choice at a glance.

### Fixed: charts stayed out of date after logging

Gauge, trend and quick-stat cards could show old numbers after you logged a
day, edited one from the calendar, or restored a backup, until something
else made the dashboard rebuild. They now refresh straight away everywhere
your log changes.

### First TestFlight build: diagnostics are debug-only

The database status icon on the dashboard and the "Database" section in
Settings were developer diagnostics. They no longer appear in release
builds. If an unlock fails, you still get the plain explanation and Unlock
button, exactly as before.

### Under the hood

Routine dependency and GitHub Actions updates, PR hygiene checks in CI, and
new design documents (personas and feature specs) for planned work. No
user-visible change. Kept here for the technically curious and for
F-Droid's changelog.

### Upgrading from 1.1.0

The on-device database upgrades itself on first launch (schema version 5 to
7): your dashboard's quick-stat choices are carried over into the new grid,
and existing gauge/trend/quick-stat cards keep their settings. Backups
exported by any earlier version still import cleanly. Because this is the
first release to run that upgrade on real devices, it must be tested from a
real 1.1.0 install before release, see the checklist below.

## Cutting this release

See `docs/deployment/release-process.md` for the full, ordered process
across Google Play, the Apple App Store (TestFlight first) and F-Droid;
this list is the 1.2.0-specific part.

- [x] Decide the version number: additive features plus a schema upgrade,
      no external breakage, so a minor bump, `1.2.0`.
- [x] Bump `version:` in `pubspec.yaml` to `1.2.0+4` (Android `versionCode`
      4, iOS build 4; build numbers must only ever increase per store).
- [x] Release notes and store "What's new" copy written (this file).
- [x] F-Droid draft metadata points at `v1.2.0` / versionCode `4`.
- [ ] Merge the diagnostics/marketing-specs PR (`remove-db-diagnostics-release`)
      first; this branch is stacked on it. If it is merged before this one,
      rebase this branch onto `main`.
- [ ] Upgrade test on a real device: install the 1.1.0 build, log some days
      and customize the dashboard, then install this build over it. Confirm
      it opens, the dashboard layout and history are intact, and an export
      made on 1.1.0 imports.
- [ ] Confirm the release build shows no database status icon on the
      dashboard and no Database or Demo data section in Settings.
- [ ] Marketing assets regenerated for this version from `docs/marketing/`
      (needs the runner; see that README), or the current screenshots
      confirmed still accurate.
- [ ] Merge to `main`, then tag `main` with `v1.2.0` and push the tag. This
      is the step that triggers the signed Android build and the iOS
      upload; do not tag from this branch.
- [ ] Paste the "Store listing copy" above into Play Console and App Store
      Connect "What's new".
- [ ] Consider replacing the auto-generated GitHub Release body
      (`generate_release_notes: true`) with the "Full release notes" above.
