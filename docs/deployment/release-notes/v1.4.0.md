# Inner Flare 1.4.0: release notes

Everything that's landed since
[v1.3.0](https://github.com/Health-Flare/InnerFlare/releases/tag/v1.3.0):
backups encrypted by default, period starts worked out from your whole log,
a "Period day" switch on the log screen, and trend cards that fit their
size.

A new "Period day" switch and a changed rule for period starts, plus one
schema change (`cycle_day_logs.period_day_override`, schema 8 to 9, added
as NULL for every existing row). Nothing is removed and older backups
still import, so this is a minor version (`1.4.0`), build number `7`.

## Full release notes

### Backups are encrypted by default

- "Encrypt export" now starts on. Turning it off shows a warning that
  anyone with the file can read everything in it.
- On phones, the backup file is deleted as soon as the share sheet is done
  with it, whether you shared it or cancelled. Leftover backup files from
  older versions are cleared when the app starts.
- File names and contents no longer say which app made them, and error
  messages no longer show technical details.
- Backups made by older versions still import.

### Period starts, worked out from your whole log

- Day 1 of a cycle is the first day of light, medium or heavy flow.
  Spotting can lead into a period but doesn't start one, and a single day
  with no flow inside a period doesn't split it.
- The order you log days in no longer matters. Logging a day before an
  existing period, or clearing flow from a day, no longer leaves an extra
  or missing period start.
- One-off spotting and single forgotten days inside a period no longer
  create short 1 to 3 day "cycles" that pulled averages down and could mark
  your cycles as irregular.
- "Days since last period", counted from the end of your period, no longer
  stops at a single day you didn't log.
- "How estimates work" explains the rule and its sources.

Some cycle lengths, averages and predictions may change after this update,
usually by a day.

### "Period day" switch

A switch on the log screen lets you decide whether a day counts as a period
day, whatever flow you logged. Turn it on for spotting you know is the start
of your period, or for a day you didn't pick a flow. Turn it off for
bleeding that isn't a period: the flow is kept and still shows on the
calendar, but it's left out of cycle lengths and predictions. "Work it out
from flow" goes back to the app's rule. Your choice is kept in backups.

### Trend cards fit their size

Cycle length trend cards now show only as many recent cycles as fit: up to
12 bars or 24 points on a line, fewer on a half-width card. A note under
the chart says how many are shown, and tapping the card still lists every
cycle.

### Insights says how many cycles it used

With more than 6 cycles logged, Insights now says the average is based on
your last 6 cycles. It used to give the total number of cycles, though only
the last 6 were used.

### Under the hood

CI supply chain hardening (pinned actions, enforced lockfile), release
APKs are no longer debuggable, an `-PunsignedRelease` build option for
F-Droid's unsigned APK, Renovate grouping and lock file maintenance. No
user-visible change.

## Cutting this release

See `docs/deployment/release-process.md` for the full, ordered process;
this list is the 1.4.0-specific part.

- [x] Decide the version number: a new switch and a changed period-start
      rule, one additive schema change, nothing removed, so a minor bump,
      `1.4.0`.
- [x] Bump `version:` in `pubspec.yaml` to `1.4.0+7` (Android
      `versionCode` 7, iOS build 7; build 6 is the last upload).
- [x] Release notes and store "What's new" copy written (this file).
- [x] F-Droid draft metadata points at `v1.4.0` / versionCode `7`.
- [ ] Upgrade test on a real device (schema 8 to 9): install 1.3.0 from
      Play, log a few cycles including spotting, customize the dashboard,
      install the 1.4.0 build over it from the internal track, and confirm
      data, layout and unlock survive. Import a backup exported by 1.3.0.
- [ ] Release-mode check: no debug-only UI (database status icon, Settings'
      Database and Demo data sections).
- [ ] Merge to `main`, then tag `main` with `v1.4.0` and push the tag.
- [ ] Play: install from internal testing, paste "What's new", promote to
      production.
- [ ] App Store: the build in review (1.3.0) has the plaintext backup
      default. Replace it with build 7 when it's processed in App Store
      Connect.
- [ ] Marketing assets: the export screenshot shows the old "Encrypt
      export" default if it was captured with the switch off; confirm or
      re-shoot.
